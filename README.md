# 원하는 포즈로 이미지 만드는 도구

[![Open In Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/tigermorning/pose-image-tool/blob/main/pose_tool.ipynb)

## 도구 설명

사진 한 장과 텍스트 프롬프트를 주면, **사진과 같은 자세를 한 다른 인물이나 장면**을 생성합니다.
OpenPose가 사진에서 관절을 뽑고 MiDaS가 깊이 맵을 뽑습니다. 두 힌트를 각각의 ControlNet이 매
디노이징 스텝에 주입하고, SDXL이 힌트에 담기지 않은 나머지를 채웁니다.

```
참조 사진 → OpenPose 관절 + MiDaS 깊이 → 힌트 2장 → ControlNet 2개 → SDXL → 결과 이미지
```

역할 분담이 이 도구의 핵심입니다. **힌트는 신체가 어디에 어떻게 놓였는지를, 프롬프트는 신체가
무엇인지를 담당합니다.**

프롬프트의 자세 서술은 금지가 아니라 조건부입니다. **힌트와 일치하는 자세 절은 스켈레톤이 담지
못하는 것(몸이 기운 방향, 무게가 실린 곳, 손이 닿은 것)을 보강해 유용하고, 힌트와 충돌하는 자세
절은 무시됩니다.** 앉은 자세를 서술한 A1을 선 자세 힌트에 그대로 보내면 스툴이 나타나지 않고,
자세 절을 뺀 프롬프트와 관절 오차가 사실상 같습니다 (노트북 진단 1). 그래서 2단계-B는 A1을
**바이트 단위로 그대로** 보냅니다 — 과제가 "같은 프롬프트"를 요구하고, 충돌하는 절은 무해하게
무시되기 때문입니다.

| 구성 요소 | 사용 모델 |
|---|---|
| 생성 모델 | `SG161222/RealVisXL_V5.0` (SDXL 사실성 파인튜닝) |
| ControlNet — 포즈 | `thibaud/controlnet-openpose-sdxl-1.0` |
| ControlNet — 깊이 | `diffusers/controlnet-depth-sdxl-1.0` |
| 포즈 검출기 | `controlnet_aux.OpenposeDetector` (`lllyasviel/Annotators`) |
| 깊이 검출기 | `controlnet_aux.MidasDetector` (`lllyasviel/Annotators`) |
| GPU | Colab 무료 **T4**로 충분 |

### FLUX.2-klein 대신 SDXL을 쓴 이유

과제는 FLUX.2-klein 4B "또는 비슷한 모델"을 제안했습니다. 그 경로를 확인한 뒤 배제했습니다.
klein은 4B가 아니라 **9B**이고 텍스트 인코더가 Mistral-Small-3.1 **24B**여서 bf16으로 약 50GB입니다.
게다가 **공식 ControlNet이 없습니다** — OpenPose 경로는 서드파티 커뮤니티 구현 하나뿐입니다.
무료 T4에서 실행이 불가능하므로, 이 노트북을 여는 누구도 재현할 수 없게 됩니다.
SDXL + OpenPose ControlNet은 `diffusers`가 정식 지원하고 무료 T4에서 fp16으로 돌아가며,
파이프라인 개념은 동일하게 시연됩니다. FLUX.1-dev 업그레이드 경로는 문서 아래에 적어 두었습니다.

## 사용법

1. **Colab에서 노트북 열기** — 위 배지를 클릭한 뒤 `런타임 > 런타임 유형 변경 > T4 GPU`를 설정합니다.
   GPU를 켜지 않으면 1번 섹션에서 즉시 중단됩니다.
2. **셀을 위에서 아래로 순서대로 실행** — 1번 설치, 2번 모델 로드, 3번 사진 업로드와 포즈 추출,
   5번 실험 두 가지, 6번 저장. 전체 약 10분입니다.
   **3a번 출력을 반드시 확인하세요.** 모든 힌트가 `18/18 keypoints, all four limb chains complete`로
   나와야 합니다. 사지 사슬이 끊긴 힌트는 그 팔다리의 포즈 제어가 조용히 꺼진 상태이고,
   이후 어떤 단계도 경고하지 않습니다.
3. **결과 이미지 저장 위치** — Colab 세션의 `samples/` 폴더이며, 6번 섹션이 `samples.zip`으로
   자동 다운로드합니다. 생성 이미지 3장과 힌트 4장입니다.

| 파일 | 내용 | 과제 단계 |
|---|---|---|
| `samples/pose_01.png`, `depth_01.png` | 참조 사진 a에서 추출한 힌트 2장 | 1단계 |
| `samples/output_01.png` | 그 힌트 + A1 프롬프트 | **1단계** |
| `samples/output_01_alt_prompt.png` | 같은 힌트·시드, 잉크 드로잉 프롬프트 (A2) | 2단계-A |
| `samples/pose_02.png`, `depth_02.png` | 참조 사진 b에서 추출한 힌트 2장 | 2단계-B |
| `samples/output_02.png` | `pose_02` + **A1과 바이트 단위로 같은** 프롬프트·시드 | **2단계-B** |

생성은 3장이고 모두 시드 1234입니다. 2단계-B는 `output_01.png`과 `output_02.png`의 대조입니다 —
프롬프트·시드·샘플러 설정이 전부 같고 스켈레톤 출처만 다르므로, 두 파일의 차이는 힌트 하나로만
설명됩니다. `A1 × pose_01`은 곧 1단계 결과이므로 같은 이미지를 두 번 만들지 않습니다.

2단계-B는 **A1을 그대로** 보냅니다. 자세 절이 선 자세와 충돌하지만, 충돌하는 절은 절충되지 않고
무시된다는 것이 측정됐으므로(진단 1) 프롬프트를 바이트 단위로 유지하는 편이 과제 요구에 맞습니다.
전문은 [`prompts.md`](prompts.md).

참조 사진 원본은 커밋하지 않습니다. `references/`는 `.gitignore` 대상이고, 공개되는 것은
추출된 스켈레톤과 생성 결과물뿐입니다. 프롬프트·시드·설정 전체는 [`prompts.md`](prompts.md)에 있고,
관찰 기록 전문은 노트북 7번 섹션에 있습니다.

## 테스트 결과

두 실험 모두 한 번에 한 가지만 바꿉니다. 포즈 재현도는 **눈으로 판단하지 않고 측정합니다.**
생성된 이미지에 OpenPose를 다시 돌려 힌트와 관절별 거리를 비교합니다
(`pose_fidelity()`, 4a번 섹션). 0.03 근처면 자세가 재현된 것이고, 0.3 근처면 다른 자세입니다.

두 참조 모두 힌트 18/18, 사지 사슬 완전, 2D 교차 없음입니다.
아래 수치 전부 **한 기계의 한 실행**에서 나왔습니다 (RTX 3060 Ti, fp16 + model CPU offload, 장당 약 10분).

| 실행 | 힌트 | 프롬프트 | 결과 파일 | 관절 오차 | 최악 관절 |
|---|---|---|---|---|---|
| 1단계 | `pose_01` 스툴에 앉아 정면 | A1 | `output_01.png` | **0.013** | r_knee 0.020 |
| 2단계-A | `pose_01` 동일 | A2 잉크·수채 드로잉 | `output_01_alt_prompt.png` | **0.012** | r_wrist 0.039 |
| 2단계-B | `pose_02` 서서 주먹 | A1과 바이트 동일 | `output_02.png` | **0.010** | r_knee 0.020 |

진단 3건은 산출물이 아니라 대조군이라 `samples/`에 저장하지 않습니다. 아래 주장들이
다른 하드웨어나 옛 구성에서 잰 값에 기대지 않도록, 같은 실행에서 다시 잽니다.

| 진단 | 무엇을 확인하나 | 결과 |
|---|---|---|
| 1 | A1에서 자세 절을 빼면 달라지나 | 거의 같음 — 충돌하는 절은 무시됨 (이전 실행 0.008 대 0.010) |
| 2 | 깊이 conditioning을 끄면 (`depth_scale=0.0`) | 오차가 약 **3배** — 이 파이프라인 최대 단일 요인 |
| 3 | 홍채가 눈 중앙에서 얼마나 벗어났나 | 눈 간격 **33 px**, 홍채 약 7 px |

**깊이 ControlNet이 이 파이프라인에서 가장 큰 단일 요인입니다.** 진단 2에서 깊이만 끄면 오차가
약 3배가 되고, 다른 어떤 설정 변경도 이만큼 움직이지 않습니다. 포즈 힌트만으로는 사지 위치는
잡히지만 몸이 기운 방향과 접촉이 자유롭게 남아 자세가 어긋납니다.

**충돌하는 자세 절은 손해를 주지 않았습니다.** 이전 실행에서 A1 원문이 0.008, 자세 절을 뺀 쪽이
0.010이었습니다. 로컬에서도 같은 방향(0.0098 대 0.0113). 힌트가 자세를 확실히 이기므로 프롬프트의
자세 서술은 무해하게 무시되고, 그래서 프롬프트를 바이트 단위로 유지할 수 있습니다.

**하드웨어를 바꿔도 결론은 재현됩니다.** 2단계-B가 로컬 3060 Ti에서 0.0100 / 0.0113, Colab T4에서
0.009 / 0.010이었습니다. 다만 **픽셀은 이식되지 않습니다** — 같은 참조·같은 코드인데 `pose_01.png`와
`depth_01.png`조차 두 기계에서 바이트가 달랐고, 어떤 프롬프트 절이 반영되는지도 갈렸습니다.
18/18 검증은 양쪽 모두 통과했습니다.

**핵심 대조**: 프롬프트를 바꾸면 자세만 남고 나머지가 전부 바뀌고, 포즈 사진을 바꾸면 자세가
바뀝니다. 이 비대칭이 결론입니다 — 힌트가 신체 위치를, 프롬프트가 신체 정체성을 담당합니다.

**다만 완전한 분업은 아닙니다.** 이전 실행의 한 쌍은 프롬프트·시드가 바이트 단위로 같은데
재킷 luma가 **109.3 대 70.2**로 255 중 39 차이였습니다. 같은 옷이 힌트만
바뀌어 3분의 1 어두워졌습니다. 인물·옷 종류·배경은 건너왔지만 톤은 힌트를 따라갔습니다. 앉은
힌트가 프롬프트에 없던 스툴을 만들어낸 것과 같은 현상입니다 — **힌트는 자세 외에 밝기와 접촉
기하도 함께 실어 옵니다.** 힌트를 바꾸는 비교에서 "프롬프트 때문"이라고 말하려면 이 점을 먼저
배제해야 합니다.

같은 파이프라인을 여러 번 돌려 확정한 설정값과 그 근거입니다.

| 확정 사항 | 측정 근거 |
|---|---|
| ControlNet 2개, conditioning은 pose 0.8 + depth 0.6 | 깊이 맵이 이미 사지를 고정하므로 포즈에까지 1.0을 주면 몸이 뻣뻣해집니다. 진단 2가 같은 프롬프트·힌트·시드로 포즈 단독 1.0과 대조합니다 |

### 이전 구성에서 기록된 결함

아래는 **현재 노트북이 돌리지 않는 구성**(ControlNet 1개, SDXL base 1.0, conditioning 1.0)에서
나온 기록입니다. 코드를 일부러 되돌려야 재현되므로 위 실행에 포함되지 않습니다. 지금 코드가 왜
이렇게 생겼는지를 설명하는 자리이지, 현재 성능 수치가 아닙니다.

| 고친 것 | 당시 측정 |
|---|---|
| 힌트를 생성 해상도에 직접 그리게 함 | 검출기 내부 리스케일에 맡기면 스켈레톤이 번져 색이 43개에서 2210개로 늘고 세로로 5% 압축됐습니다. 그 상태에서 SDXL이 **다리를 3개** 그렸습니다 |
| ControlNet이 포즈 하나뿐일 때는 1.0이 필요 | 0.8에서 접힌 무릎이 화면의 0.448만큼 힌트를 이탈했습니다(평균 0.099). 1.0에서는 전 관절 0.066 이내(평균 0.031)였습니다. 깊이 ControlNet이 붙은 지금은 이 결론이 뒤집힙니다 |
| 참조 사진은 중앙 크롭이 아니라 레터박스 | 355x592 사진에서 중앙 크롭이 높이의 12%를 잘라내 왼쪽 발목을 프레임 밖으로 밀어냈고, 키포인트가 18/18에서 17/18로 떨어졌습니다 |
| 손 키포인트는 켠 상태 유지 | 이 ControlNet에서는 손 검출을 끄라는 권고가 있으나, 실측 결과 끄면 짚은 손목 오차가 0.028에서 0.278로 악화됐습니다 |

## 한계

### 작은 특징은 프롬프트가 닿지 못합니다 — 이 도구의 핵심 한계

손가락, 눈, 표정이 모두 같은 이유로 실패합니다. **프레임에서 차지하는 픽셀이 너무 적습니다.**
자세 제어는 0.010대로 정확한데 얼굴과 손은 통제 밖이라는 비대칭이 이 파이프라인의 성격입니다.

`output_01.png`에서 실측한 크기:

| 부위 | 크기 | 결과 |
|---|---|---|
| 두 눈 사이 간격 | **33 px** | 홍채는 약 7 px |
| 눈 하나가 들어가는 창 | **28 x 17 px** | 홍채 위치를 텍스트로 지정할 수 없음 |

**시선을 프롬프트로 고치려는 시도는 측정으로 실패했습니다.** 머리 방향은 힌트가 정면으로 잡습니다
(참조의 코가 두 눈 중점·두 귀 중점과 0.008 이내로 일치, 귀 양쪽 검출). 그런데 홍채만 한쪽으로
쏠려 얼굴 방향과 시선이 어긋납니다. 두 가지를 시도했고 둘 다 역효과였습니다.

| 시도 | 홍채 오프셋 (0 = 중앙) |
|---|---|
| A1 원문 | +0.096 |
| 같은 프롬프트, 다른 GPU | +0.108 |
| `looking straight into the lens` 추가 + 네거티브에 `averted eyes, cross-eyed, blank stare` 등 8항목 추가 | **+0.157 — 더 나빠짐** |

양쪽 눈의 오프셋이 0.02 이내로 일치하므로 노이즈가 아닌 실제 편향입니다. 7 px짜리 대상은
디노이징 경로가 결정하고 프롬프트는 그 아래에 닿지 못합니다. **육안으로는 개선된 것처럼
보였고 측정은 반대였습니다** — 그래서 `gaze_offset()`(진단 3)이 존재합니다.

- **손은 고치지 못했습니다.** `output_01.png`의 두 손 모두 손가락 개수와 방향이 틀렸습니다.
  프레임에서 손이 **약 54 px**이라 손가락 하나가 10 px 남짓이고, 이 크기에는 참조할 형태 정보가
  없습니다. 손 영역만 1024로 확대해 다시 그리는 인페인팅을 9회 시도했으나 해부학적으로 맞는 손이
  한 번도 나오지 않았습니다 — 크롭을 좁히면 손가락은 분리되지만 주변 맥락이 사라져 배경이 다른
  것으로 바뀌고, 넓히면 맥락은 유지되나 손가락이 다시 뭉개집니다. **프롬프트 문제도 마스크 문제도
  아니라 해상도 문제입니다.** 실제 해법은 손 전용 리파이너(MeshGraphormer 깊이 + hand ControlNet),
  손이 크게 담기는 참조, 또는 더 높은 생성 해상도이며 모두 이 도구의 범위를 넘습니다.
- **신발이 좌우 다릅니다.** 프롬프트가 신발을 지정하지 않아 모델이 발마다 다른 것을 발명했습니다 —
  땅에 닿은 발은 두꺼운 플랫폼 솔, 스툴에 올린 발은 얇은 로우 스니커. 스켈레톤은 신발에 대해
  아무 말도 하지 않으므로, 프롬프트도 말하지 않으면 한 켤레로 묶어 줄 것이 없습니다.

### 그 외
- **포즈 힌트는 조용히 실패합니다.** 엉덩이-발목 사슬이 끊기면 자세가 틀리게 나오는 것이 아니라
  **무난한 기본 자세**가 나옵니다. ControlNet이 강제할 것이 없으니 모델이 자기 사전지식으로
  되돌아가기 때문입니다. 실행 중 어디에서도 경고하지 않습니다. 3a번 섹션이 생성 전에 이것을 잡아내며,
  후보 참조 사진 6장 중 4장이 여기서 탈락했습니다.
- **검출을 깨뜨리는 것은 가림입니다.** 코트 안으로 들어간 팔은 사지 사슬 하나를 통째로 잃었고(15/18),
  상반신 위주 사진은 다리 관절이 하나도 잡히지 않았습니다(12/18).
- **스켈레톤은 2D이고, 깊이는 별도 힌트가 메웁니다.** 스켈레톤만으로는 겹친 팔다리를 구분할 수
  없어 MiDaS 깊이 맵을 두 번째 ControlNet으로 함께 넣습니다. 깊이 맵은 프롬프트에 없는 것까지
  만들어냅니다 — 자세 절이 없는 프롬프트인데도 앉은 힌트에서 **스툴이 그려졌습니다**. 머리가
  향하는 방향도 힌트가 정합니다. 프롬프트로 지정하려는 시도는 위에서 측정으로 실패했습니다.
- **구도는 포즈와 독립적으로 정할 수 없습니다.** 크롭이 스켈레톤의 화면 점유 범위를 따라갑니다.
- **프롬프트의 절들이 균등하게 반영되지 않습니다.** 구체적인 쪽이 이깁니다 — 재질과 광학 현상을
  함께 적은 절은 그려지고, 추상 명사 하나만 있는 절은 무시되는 경향이 있습니다. 구체적이어도
  실패하는 절이 있습니다. `cropped jacket`은 **로컬 3060 Ti와 Colab T4 양쪽에서, 힌트와 프롬프트를
  바꿔 가며 생성한 모든 이미지에서** 무시되고 엉덩이 길이 오버사이즈 블레이저가 나왔습니다.
  또한 텍스트 인코더가 77토큰에서 **뒤쪽부터** 조용히 잘라내므로, 프롬프트를 수정할 때마다
  토크나이저로 확인해야 합니다 — A1 66/77, A2 65/77, 자세 절 뺀 프롬프트 40/77, 네거티브 44/77.
- **어떤 절이 반영되는지는 고정되어 있지 않습니다.** 바지 밝기를 표본해 확인했습니다.

  | 프롬프트 | 기계 | 힌트 | 바지 luma |
  |---|---|---|---|
  | A1 (66토큰) | 3060 Ti | pose_01 | **57.8** 어두움 |
  | A1, 바이트 동일 | 3060 Ti | pose_02 | **55.1** 어두움 |
  | A1, 바이트 동일 | **T4** | pose_01 | **99.1** 밝음 |
  | 자세 절 뺀 것 (40토큰) | T4 | pose_01 / pose_02 | 127.8 / 144.3 밝음 |

  `wide dark trousers`가 로컬에서는 지켜지고 **T4에서는 같은 프롬프트·시드·설정인데 무시됐습니다.**
  즉 `dark`의 실패는 프롬프트 통제력의 고정된 한계가 아니라 **기계에 따라 갈립니다.** 반면
  `cropped jacket`은 어디서도 지켜지지 않았습니다 — 둘을 같은 등급으로 적으면 안 됩니다.

  프롬프트를 짧게 줄인 쪽에서 힌트 간 색 차이가 커진 것도 같은 맥락입니다. 재킷 luma의 힌트 간
  차이가 A1에서는 9.9, 자세 절을 뺀 40토큰 프롬프트에서는 39.1이었습니다. **프롬프트가 덜 지정한
  만큼 힌트가 채웁니다.**
- **네거티브 프롬프트는 억제일 뿐 보증이 아닙니다.** `text`와 `watermark`를 넣었는데도 배경 벽에
  뭉개진 글자가 렌더링된 이미지가 있었습니다. 같은 시드·같은 힌트의 다른 프롬프트에서는 깨끗했습니다.
  이것도 육안 관찰입니다.
- **관절 점수가 보지 못하는 것이 있습니다.** `pose_fidelity()`는 사지 12관절 **좌표만** 비교합니다.
  손가락·얼굴·옷 기장은 채점에 안 들어가므로, 평균 오차 0.01과 "손이 뭉개졌다"는 관찰이 동시에
  참일 수 있습니다. 모순이 아니라 지표의 범위입니다.
- **사실성은 base 모델이 정합니다.** SDXL base 1.0은 얼굴과 피부가 마네킹처럼 나왔고 프롬프트나
  샘플러 설정으로 고쳐지지 않아 `SG161222/RealVisXL_V5.0`으로 교체했습니다. 그보다 더 올리려면
  설정이 아니라 base 모델을 다시 바꿔야 합니다.

### FLUX.1-dev 업그레이드 경로

2번 섹션을 `black-forest-labs/FLUX.1-dev` + `Shakker-Labs/FLUX.1-dev-ControlNet-Union-Pro-2.0`의
`pose` 모드로 교체하면 됩니다. 대가는 유료 L4/A100 런타임과 8bit 양자화, 게이트 저장소용
Hugging Face 토큰, 그리고 `guidance_scale` 재조정입니다. 노트북 구조와 `generate()` 인터페이스는
그대로 쓸 수 있습니다.
